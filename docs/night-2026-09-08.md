# The night of 7–8 September 2026

What changed, what is proven, and what is still open. Written so that the next
session can trust the "proven" column without re-deriving it.

## Shipped and verified

**Layout presets.** Five built-ins (`comfortable`, `compact`, `minimal`,
`horizontal`, `shy`) plus four custom slots, all backed by prefs so
`about:preferences` and the window apply the same state. Presets carry per-state
widget configuration across four states — `normal`, `emptyTab`, `tor`,
`torEmptyTab`.

**The fourth state was forced by the data, not chosen.** `hiddenWidgetsFor`
resolves "last active state wins", so with three states Tor always outranks the
empty tab: `unrouted` is expressible and `always` is not. Their intersection had
to become its own state. It is also exactly the case the user raised — an empty
tab inside a Tor window is neither of its parents.

**Right rail.** A real `CustomizableUI` area, so it is droppable and survives
Customize Toolbar. Being a real `<toolbar>` is also why it needed no fullscreen
rule of its own.

**Tor.** Our own `/usr/bin/tor` under the profile, SAFECOOKIE auth, per-space
circuit isolation via `newProxyInfoWithAuth` (`newProxyInfo` has no credential
parameters — the earlier code was silently putting them in the authorization
header, and both Tor spaces shared one circuit). Panel reads a real circuit:
hops with nicknames and countries, `SIGNAL NEWNYM`, `ONEHOP_TUNNEL` filtering,
onion-service indicator. Bridges (obfs4, snowflake) validate and resolve to
torrc lines *before* tor is spawned, so a bad line never starts a broken daemon.

**Privacy.** Per-site `keep`/`session`/`tab` lifetimes expressed as Gecko
permissions; per-site clear with honest scope. A per-site clear had been calling
`deleteAll()` on the auth cleaners — it would have signed the user out of every
site.

**The urlbar return jump — fixed, after five attempts.** Root cause was not in
either module that writes the width. `_repair()`'s guard reads
`if (!url || !cont || this._open) return;`, and `close()` clears `_open` on its
first line, so for the whole 260 ms return glide the 1 s repair sweep saw a
still-centred field with `_open === false`, judged it stranded, and stripped the
inline pin mid-flight. 288 cycles under load, 0 failures, worst frame-to-frame
0.7 px, resting and settled rects pixel-identical (`bbox: None`). Centring is on
by default.

**Chrome no longer paints over fullscreen video.** Upstream collapses
`#navigator-toolbox` and every `<toolbar>`, and nothing else;
`#zen-horizontal-chrome` is neither, so it left a 77 px band over the page. Same
guard now on the Activity and clipboard toasts, which are `position: fixed` on
the root.

## Regression harness

`scripts/regress.py` — ten checks plus a browserless `patches-apply`
pre-flight. Free port per run, per-port profile, `media.volume_scale = 0`.
`urlbar-return-no-jump` samples with rAF rather than a timer, so it compares
composed frames; proven still to fail on a deliberately reintroduced jump.

A check that raises no longer takes the next one down with it — a script
timeout wedges the Marionette session, so the runner now reconnects. The Tor
check has 600 s rather than 300 s (three real loads came to 273.6 s worst case)
and retries a failed onion descriptor fetch once; the leak probe deliberately
gets no retry, since "it did not load" is exactly what it asserts.

Current state: **0 failed, 0 skipped**, including against the packaged binary.

## Judgement calls made, with reasons

- **No `ZenStackCard` base class.** `.zen-stack-card` and the shared
  `gZenCardStack` already give Activity and media cards identical surface, size
  and peek (both measured at 181 px). A JS base would be inert for Activity,
  which never sets `hidden` for tab selection, and would split it from its real
  siblings — every other `ZenPageCards` card, Tor's route card included.
- **F11 left alone.** It is not broken: `#nav-bar` carries
  `fullscreentoolbar="true"`, so the chrome stays live and in flow. And
  `fullscreenNavToolboxHidden` is set while `#navigator-toolbox` still paints,
  i.e. the reveal machinery is already inert in this preset — not something to
  hang the urlbar's only way back on.
- **No arti.** `arti-client` is 0.46 with 44 direct dependencies; the single
  functional gap is "tor is not installed", better solved by saying so.

## Open

- The `.desktop`/`BuildID` collision: the packaged `application.ini` and the id
  compiled into `libxul.so` differ, and the latter matches the currently
  installed build. The startup-cache purge in `tela-zen.install` is therefore
  load-bearing, not belt-and-braces.
- `npm run import` has not been run end to end since it was fixed; only its
  git-patch stage was simulated against pristine (255/255 apply).
- No native code has been recompiled since 2 September. Nothing in this work
  needed a compiler — but a full clean rebuild is not possible on this host
  (11.1 GB free; `libxul.so` alone is 2.4 GB unstripped, and a full build has
  frozen the machine before).
- Widget rows in Settings are named from the node's `label`/`tooltiptext`. An
  extension's browserAction button takes the same path but was never seen, since
  a fresh profile has no extensions.
